# P1 checkpoint: verified data and live detection

Date: 2026-11-06.

## P1A data (passed)
Command: `python scripts/prepare_data.py --config configs/data.yaml` (97 s, 7 workers).

* 8,144 train and 8,041 test records; all 196 classes in both; 24 to 68 images per class.
* Every annotated file exists, no unannotated files, every image decodes (16,151 RGB, 34 grayscale).
* `cars_test_annos_withlabels.mat` SHA256 matches TFDS published value.
* Box convention: 1-based inclusive confirmed (minimum x1 is 1, x2 never exceeds width, x2 equals
  width 431 times). Canonical = zero-based half-open; converted once in `src/vision/coordinates.py`.
* 30-sample overlay sheet inspected: `reports/figures/data_overlays_m1.png`; boxes align.
* EXIF: 32 images have an invalid tag 0, one has tag 6 (`train/07389.jpg`). Its stored pixels are
  upright and the box matches them, so dataset images never apply EXIF. Uploads do.
* Duplicates: 39 byte-identical groups; **37 have conflicting labels** (usually neighbouring
  classes, e.g. two model years). 19 official test images have an exact copy in the train pool.
  Recorded in `reports/data_audit.json`; official test population unchanged. P6 will report a
  duplicate-excluded diagnostic next to the 8,041 headline.
* Partitions (seed 20261106): train 6,514 (196 classes), tune 815 (196), calibration 815
  (194 classes; acceptable for marginal calibration), test 8,041 (196). Key-disjoint; exact
  content overlaps between partitions are listed in the audit (from the duplicates above).
* Manifest hashes identical across three runs (determinism check).
* All 196 metadata rows reviewed; 49 makes; 7 year-only families; others attach to make.

## P1B detection (passed locally; Docker run and public deploy blocked)
* YOLO11n (COCO, Ultralytics 8.4.203), SHA256 `0ebbc80d4a76...`, car/bus/truck mapped to vehicle.
* Fixed target rule: largest vehicle box with score >= 0.25 (development value).
* Bounded decode: 10 MB, 25 MP, long edge 1600, EXIF applied, transparency flattened.
* Readiness only after checksum verification and a real warmup inference.
* Found and fixed: Ultralytics patches `PIL.Image.open` and tries to `pip install pi-heif`
  on unidentifiable uploads. Disabled; tests confirm no install attempt.
* 24/24 tests pass (`python -m pytest`), including real detection on a Stanford test image and
  invalid, empty, oversized, too-many-pixels, blank, grayscale, transparent and misnamed inputs.
* Browser check (local uvicorn): upload draws the box on the car; phone width (375 px) has no
  horizontal scroll; invalid file shows a clear recovery message.
* Local single-image server timing (one warm request, not a latency claim): decode 30 ms,
  detection 145 ms.
